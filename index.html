Project Overview

Why Build a Private Offline AI?

Cloud AI models offer immense capabilities but require sending proprietary source code, private business records, or personal thoughts to third-party data centers. This project solves that security compromise.

The Confidentiality Challenge

When working with sensitive medical records, proprietary codebases, intellectual property, or confidential client data, uploading context to remote APIs creates regulatory and operational liability.

  • Cloud APIs may log queries for training or safety evaluation.
  • Network transmission exposes payloads to man-in-the-middle risks.
  • Internet outages render cloud tools unavailable.

The Local Architecture Solution

By combining an optimized quantized model (Qwen 2.5 1.5B), the Ollama runtime, a custom zero-dependency Python backend, and a reactive frontend, complete ChatGPT-level ergonomics run entirely inside a Windows laptop.

  • Zero bytes leave the computer: True loopback isolation.
  • Zero telemetry: No telemetry SDKs, analytics, or trackers.
  • Zero disk persistence: Ephemeral volatile RAM context only.

Deep Dive

How It Works

Examining the mechanics behind the local offline application and comparing it with this static portfolio showcase.

1

Local Model Packaging & Quantization

In the real application, the AI model is Qwen 2.5 1.5B, quantized using 4-bit integer weights (Q4_K_M). This reduces the memory footprint to ~986 MB, allowing the entire neural network to fit comfortably inside the 4 GB VRAM of an entry-level mobile GPU (GTX 1650).

2

Zero-Dependency Python Micro-Gateway

The local backend uses Python 3's built-in ThreadingHTTPServer and urllib.request. It enforces strict HTTP origin headers, sends Cache-Control: no-store, no-cache security headers, streams Server-Sent Events (SSE) directly from Ollama to the browser, and explicitly silences server access logs to guarantee zero prompt traces on disk.

3

Public Portfolio Simulation Layer

For this public GitHub Pages portfolio, the client-side JavaScript implements an honest mock chat. It provides curated real outputs for technical questions (SQL, C++, local AI principles, computer architecture) and clearly alerts visitors when arbitrary text is submitted that no real AI model is executing online.

Security Guarantees

Privacy & Security Disclosure

Honest, comprehensive transparency regarding what this public demonstration does, what the local engine guarantees, and what external limits exist.

Public Demo Privacy Boundaries

  • Zero Transmission: Visitor inputs into the interactive demo are processed purely in client-side JavaScript memory. No API or developer server receives them.
  • Zero Client Storage: The demo does not use localStorage, sessionStorage, IndexedDB, or cookies to persist chats. Refreshing the browser instantly wipes state.
  • Static Hosting Operational Metadata: Like any website on the internet, the static hosting provider (GitHub Pages) receives ordinary HTTP connection metadata (visitor IP address, User-Agent, referer) for logging and DDoS mitigation.
  • Advisory: Because this is an open public demo, visitors should never enter confidential, sensitive, or proprietary data into online browser inputs.

Local Engine Air-Gap Guarantees

  • Physically Offline: The local Python server and Ollama backend run with Wi-Fi switched off or Ethernet unplugged.
  • Strict Loopback Isolation: The backend binds exclusively to 127.0.0.1:8765 and rejects non-loopback Host or Origin headers.
  • Zero Disk Writes: HTTP request logging is suppressed. Prompts, completions, and conversation history are never written to disk, SQLite, or log files.
  • OS Reality Disclosure: The application does not claim to alter Windows OS swap files (pagefile.sys) or hibernation files (hiberfil.sys). For maximum security, running in an InPrivate browser window is recommended.
Engineering Honesty

Technical Limitations

Transparent disclosure of trade-offs between local lightweight models and commercial cloud platforms.

Public Demo Limitations

The public demo cannot generate novel AI responses to arbitrary inputs. Responses are either matched against curated demonstration samples or routed to a transparent explanation explaining demo mode constraints.

1.5B Parameter Model Scope

Qwen 2.5 1.5B is engineered for efficiency on modest hardware. While proficient at coding snippets, concise explanations, and standard queries, it cannot compete with 70B+ parameter models on multi-step philosophical nuance or complex mathematical proofs.

Single-User Loopback Design

The application is intentionally single-user and local. It does not provide multi-tenant authentication, user accounts, or remote network access by design.

Step-by-Step Guide

How to Run the Real Local Version

Run the genuine offline AI application on your own Windows computer in 5 simple steps.

1

Install Ollama on Windows

Download and install Ollama for Windows from the official site. Verify installation in PowerShell:

POWERSHELL
ollama --version
2

Pull the Quantized Qwen 2.5 Model

Download the 1.5-billion parameter model (approx 986 MB):

POWERSHELL
ollama pull qwen2.5:1.5b
3

Start the Python Backend

Navigate to the project directory and launch the standard library server:

POWERSHELL
python app.py
4

Open the Local Web Interface

Open an InPrivate / Incognito browser window and navigate to:

BROWSER URL
http://127.0.0.1:8765
5

Verify 100% Offline Operation

Disconnect Wi-Fi or unplug Ethernet. In PowerShell, test internet connectivity:

POWERSHELL (WI-FI DISCONNECTED)
Test-Connection 8.8.8.8 -Count 1 -Quiet
# Returns: False (Proving zero network egress)

Submit questions in the interface at http://127.0.0.1:8765. Tokens stream locally with zero network connection!
